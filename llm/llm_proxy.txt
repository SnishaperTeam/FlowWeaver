llm_proxy.txt — 代理服务器核心（proxy/）
==========================================

职责：真正的代理数据面。HTTP/CONNECT 代理 + SOCKS5，按 RuleManager 匹配的
Rule 决定每个连接怎么走；同时持有配置（settings/rules 的读写也在这里）。


核心类型
--------
  ProxyServer   proxy.go — 服务器主体：http.Server、证书缓存、DoH 解析器、
                CF IP 池、SOCKS5、ECH 热补丁缓存、迁移会话缓存、流量计数、
                TUN 绑卡开关（tunMode）。
                关键字段：rules(*RuleManager)、dohResolver、cfPool、mode。
  Rule          单条规则：Domain、Mode（mitm/transparent/tls-rf/quic/direct/
                migration）、SniFake、ECH*、NAT64*、CertVerify、DNSMode、
                Upstream(s)、UseCFPool。
  SiteGroup     站点分组（rules/config.json 的基本单元）→ buildRules 展开成 Rule。
  SettingsConfig 所有应用设置的结构体（listen_port、tun、语言、主题、CF 配置…）。
  TUNConfig / TUNStatus / ECHProfile / NAT64Profile / DNSNode / Upstream / CloudflareConfig
                都定义在 proxy.go，被 app 层直接透传给前端。


文件逐一说明
------------
  tunnel.go       ★ 请求入口：handleRequest → CONNECT 走 handleConnect，
                  其余走 handleHTTP。handleConnect 按 effectiveMode 分发：
                  quic → handleQUICMITM；migration → handleMigration；
                  mitm → handleMITM；tls-rf → handleTLSFragment；
                  其余 → handleTransparent。含 isSelfTarget 防自连死循环、
                  directConnect、directTunnel（128KB 缓冲池双向拷贝）。
  proxy.go        ProxyServer 定义 + HTTP 代理主体 + upstreamTLS（上游 TLS
                  建连：单 IP 两次 ECH 机会 / 多 IP Happy Eyeballs 竞速、
                  ECH 被拒后的 recoverECHConfig：服务端 RetryConfigList →
                  DoH 刷新）+ DoH 适配器 dohProxyAdapter + GetStats。
  mitm.go         TLS 中间人：给客户端发本地 CA 签的证书，解开 TLS 后按规则
                  重新封装上游（SNI 伪装 / ECH / ALPN），组织名 "SniShaper"。
  tls_fragment.go TLS-RF 分片模式：调 pkg/tlsfrag 把 ClientHello 在 SNI 最后
                  一个点处拆包发送，绕过基于 SNI 的阻断。
  migration.go    迁移模式（QUIC 连接重建）：会话票缓存、dummy 证书、
                  handleMigration / fetchMigrationTicket（用 ticket 恢复
                  TLS 会话，避开阻断）。
  socks5.go       SOCKS5 入口：go-socks5 库 + 自定义 ConnectHandle，把
                  SOCKS5 CONNECT 喂进同一套 prepareConnect/规则分流；
                  支持用户名密码认证；socks5Tracker 追踪底层连接。
  dialer.go       拨号层：buildDialCandidates（DNSMode 排序 IPv4/IPv6、
                  CF 池、NAT64 前缀映射）、dialWithRule（按规则建 uTLS 连接）、
                  TUN 下绑定物理网卡。
  cert_verify.go  上游证书校验策略（CertVerifyConfig）：chain-only /
                  allow-unknown-authority / 名称、后缀、SPKI pin 匹配。
  auto_routing.go AutoRouter：GFWList + Cloudflare 域名判定 → Decide(host)
                  给出 direct/proxy；带缓存清理协程。
  rules_manager.go ★ 配置中枢：NewRuleManager(settingsPath, rulesPath)；
                  LoadConfig 读 config/settings.json + rules/config.json；
                  buildRules 把 SiteGroup 展开成匹配规则；matchRule 是
                  路由决策点；一整套 Get/Set（端口、SOCKS5、语言、主题、
                  自启、托盘…）都写回 settings.json；SaveConfig。
  rules_merge.go  导入配置时的合并策略（ImportConfig/ImportConfigWithSummary，
                  按域名集合 key 去重合并）。
  rules_watch.go  文件监听：rules/config.json 变化 → 自动重载 + 触发回调
                  （app 层借此做热更新）。
  config.go       ExportConfig / ImportConfig（配置导出导入 + 摘要）。
  helpers.go      小工具：normalizeHost（去尾点/端口）、ensureAddrWithPort、
                  dedupeDialCandidates、normalizeDNSMode、gfwListCachePath。
  tun_flow.go     PlanTUNFlow：TUN 流量的“预演”——输入 flow（协议/主机/SNI），
                  输出该走什么模式、能否 MITM、拨号候选；供 TUN 数据面与
                  诊断 UI 用。
  port_manager*.go        端口占用：找进程、杀进程（Windows/Linux/其他），
                  IsPortInExcludedRange。
  port_manager_windows.go 注释里有 netstat 对照说明。


改动注意
--------
  - 改 rules/config.json 相关逻辑 → 验证站点分组、MITM/ECH 模式
  - 规则匹配改一处即可（matchRule），别在各 handler 里散落判断
