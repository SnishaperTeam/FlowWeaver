一、规则进化 evolution/
----------------------
目的：对一批域名自动探测"哪种方案能通"，把结果固化成站点分组规则。

  tester.go        Tester：编排测试任务（StartTest/StopTest/GetTask/Snapshot）。
                   单域名按阶梯试探：direct → tcping(IP 连通) →
                   domain fronting → TLS 分片 → ECH → QUIC → 按临时规则实测；
                   失败时可走 NAT64 回退（tryNAT64Fallback）。并发可配。
  rule_generator.go GenerateRule(domain, method, ...) → TempRule；
                   ToSiteGroup() 转成能直接写进 rules/config.json 的分组；
                   inferWebsite 猜站点名。
  result.go        TestConfig / DomainTestResult / 步骤结果等数据结构，
                   DefaultTestConfig()。

入口：UI 的 Evolution 页（app/app_evolution.go 桥接，事件
evolution:progress / evolution:complete），或 CLI `snishaper evolution …`。


二、配置文件
------------
  rules/config.json   规则主文件（约 3800 行），顶层 5 个键：
        site_groups   站点分组（域名集合 + mode/mitm/tls-rf/quic/direct…）
        upstreams     上游（类型 cf_preferred 等）
        dns_nodes     DNS/DoH 节点（URL、SNI、IP、ECH、QUIC、证书校验）
        ech_profiles  ECH 配置（config、discovery_domain、自动更新）
        nat64_profiles NAT64 前缀
      同目录可放 gfwlist_cache.txt（GFWList 本地缓存，仅启动读取）。
      读写逻辑全在 proxy/rules_manager.go；文件变化由 rules_watch 热加载。

  config/settings.json 应用设置：listen_port、socks5_port、close_to_tray、
      auto_start 系列、auto_routing、tun、language、theme、
      cloudflare_config.preferred_ips… （结构体 = proxy.SettingsConfig）

  导出/导入：app_api 的 ExportConfig/ImportConfig（合并摘要见
  proxy/rules_merge.go）。


三、构建 / 打包 / CI
--------------------
  build_windows.ps1   ★ Windows 构建入口（交互菜单 + 参数）：
        .\build_windows.ps1 -Build all|backend|frontend -Silent [-BuildMsix]
        内含 EN/CN/RU 文案表、构建计划、MSIX 打包
  build.sh            Linux/macOS 构建菜单（同结构）
  Makefile / Taskfile.yml  便捷任务入口
  winres/ + _windows_amd64.syso   Windows 图标/版本资源
  Package.appxmanifest MSIX 清单（版本号会被 app_api.manifestVersion 解析）
  devcert.pfx         开发证书（密码 password）
  .github/workflows/  _release_pipeline.yml 发布流水线、unit-test.yml
                      单测（会生成 zz_generated_scan_test.go）
  .github/scripts/    发布说明生成、测试生成脚本；ChineseSimplified_2.isl 安装器语言包


四、测试与工具
--------------
  test/               按包分组的 Go 测试：test/common、test/evolution、
                      test/pkg/{cfpool,rules,tlsfrag}、test/proxy，
                      另有 verify_build_scripts.py 校验构建脚本
  各包内 *_test.go     单元测试（netiface、singtun.fakeip、cert 等）
  仓库没有统一 test 框架配置 —— 跑 `go test ./...` 即可
  tools/              辅助脚本：scanner.py（IP 扫描）、test_dns.py、
                      spotify/supabase 规则探测脚本与日志（tools/logs/）
